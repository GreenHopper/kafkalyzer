# Proposal: material-ui-migration-tracking (Q-10)

## Why

The app is meant to use `package:material_ui` everywhere (`openspec/config.yaml`,
UI & UX). The theme is the one exception. `flex_color_scheme` 8.x builds
legacy `package:flutter/material` `ThemeData`, so `lib/src/theme.dart` and
`lib/src/flex_theme_bridge.dart` (1 292 L) import the deprecated library and
copy the legacy theme field by field into a material_ui `ThemeData`.

The bridge is also unsafe to touch. It is labelled "generated by
`scripts/gen_flex_theme_bridge.py`", but the checked-in file contains
hand-written helpers that the generator never emits (ColorScheme,
InputBorder, FloatingLabelAlignment and the AppBar/InputDecoration theme
wrappers). Running the generator today shrinks the file by 210 lines and
breaks `flexThemeToModern maps core theme values`: the primary colour falls
back to the default. The generator also hard-codes one developer's Flutter SDK
path.

Backlog `design/code-quality-refactoring-backlog.md` §3 Q-10 (change id
`material-ui-migration-tracking`, §8).

**Upstream has migrated.** `flex_color_scheme` **9.0.0** (2026-09-15,
`flutter >=3.47.0`) depends on `material_ui ^1.0.0` and returns material_ui
`ThemeData` directly. That resolves backlog item #310. So this change deletes
the bridge instead of re-baselining it.

**Spike (2026-11-23, throwaway worktree at `9440287`, Flutter 3.50.1):** I set
`flex_color_scheme: ^9.0.0` (resolves 9.0.0, `flex_seed_scheme` 5.0.1),
removed the bridge, generator and bridge test, and dropped `flexThemeToModern`
and the `legacy.` prefixes in `theme.dart`. Results:
- `flutter analyze`: no issues.
- `flutter test`: all 1 362 tests pass (the 4 bridge tests are gone).
- No hand-written file imports `package:flutter/material.dart` any more.
- The light and dark theme values are identical to today's: brightness, M3,
  visual density, NoSplash, font, primary/onPrimary/secondary/surface/scaffold
  colours, and input border radius.
- One difference: the input border is now fcs 9's state-aware border. The old
  bridge flattened it to a plain `OutlineInputBorder`. Same radius.

## What Changes

1. **Dependency**: `flex_color_scheme: ^8.3.1` → `^9.0.0`.
2. **Theme**: `lib/src/theme.dart` returns `FlexThemeData.light/dark` directly,
   with no `legacy` import and no bridge.
3. **Delete**: `lib/src/flex_theme_bridge.dart`,
   `scripts/gen_flex_theme_bridge.py`, `test/src/flex_theme_bridge_test.dart`.
4. **Theme regression test** `test/src/theme_test.dart`: pins the theme values
   from the spike, so a future fcs or material_ui bump that changes the
   app's look fails a test.
5. **Legacy Material import guard** (`legacy-material-guard`) in
   `scripts/quality_gates.sh`: rejects any hand-written Dart source under `lib/`
   or `test/` that imports or exports `package:flutter/material.dart` or
   `package:flutter/cupertino.dart`. Absolute, no exception list. Generated
   sources are exempt. Includes fixture tests.
6. **`openspec/config.yaml`**: drop the bridge from the generator-owned list;
   state that the gate enforces the material_ui-only rule; add the guard to
   verification step 6. **Backlog**: Q-10 marked implemented.

## Capabilities

### New Capabilities

None.

### Modified Capabilities

- `static-analysis-gates`: ADDED *Legacy Material Import Guard*.

The theme change itself has no spec delta. The look stays the same, the new
test pins it, and no existing spec describes the bridge.

## Impact

- **Code**: `pubspec.yaml`/`pubspec.lock`, `lib/src/theme.dart`, three files
  deleted (−1 913 lines), one new test, `scripts/quality_gates.sh` +
  `scripts/test_quality_gates.sh`.
- **Runtime**: same colours and typography. Text-field borders now follow the
  widget state (focus/error) the way fcs 9 defines them.
- **Read-only**: no new Kafka or Schema Registry calls.

## Non-goals

- **Pinning the Flutter version in CI.** The backlog asked for it only because
  SDK bumps broke the bridge, and the bridge is gone. fcs 9 sets its own floor
  (`flutter >=3.47.0`).
- **The generated `lib/l10n/app_localizations.dart`.** gen-l10n still imports
  `flutter_localizations` and lists its delegates there. It is generator-owned
  and exempt from the guard. The app already registers material_ui's
  `GlobalMaterialLocalizations.delegates` (`lib/src/app.dart`). About 80 test
  files use `AppLocalizations.localizationsDelegates` (the gen-l10n list).
  Moving them to the material_ui delegates is a possible follow-up; it is not
  needed for this change.
- Any visual redesign or theme-value change.

## Prerequisites

None. `ci-quality-gates` and `verify-generated-bindings` (gate script and
fixture harness) are merged.
