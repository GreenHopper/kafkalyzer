# Proposal: verify-generated-bindings (Q-9)

## Why

The Dart ↔ Rust bridge is generated code that is checked in:
`lib/src/rust/frb_generated*.dart`, `lib/src/rust/api.dart`,
`lib/src/rust/api/*.dart` and `rust/src/frb_generated.rs`. Nothing checks
these files against `rust/src/api/`. If a change edits a bridge function or
DTO and forgets `flutter_rust_bridge_codegen generate`, the build can still go
green: Dart calls bindings that no longer match the Rust side, and the mismatch
first shows up at runtime as a decode error or a crash. The checked-in mockito
mocks have the same problem (`test/**/*.mocks.dart`, regenerated by
`dart run build_runner build`). They drift silently when a mocked signature
changes, and then tests exercise a fake that no longer matches the real API.

Backlog `design/code-quality-refactoring-backlog.md` §3 Q-9 (change id
`verify-generated-bindings`, §8).

**Spike (2026-11-23, throwaway worktree at `HEAD` `ab49592`):** both
`flutter_rust_bridge_codegen generate` (2.11.1, 12 s) and
`dart run build_runner build` left **zero diff**. The guard can therefore land
green, with no regeneration commit first.

## What Changes

1. **Generated-code drift guard** in `scripts/quality_gates.sh`, new entry
   point `bindings-guard`, also run in the full gate:
   - Checks that the generator version on the machine matches the pinned
     bridge version (`pubspec.yaml` and `rust/Cargo.toml`, both `2.11.1`).
     A missing or different generator is a tooling error, not a pass.
   - Refuses to run when generated files already have uncommitted edits, so
     it never overwrites work in progress.
   - Runs both generators, then fails if any tracked file changed or a new
     untracked file appeared, and names each file.
2. **CI**: the `quality-gates` job installs the pinned generator before
   running the gate script (install method chosen by spike task 1.1).
3. **Fixture tests** for the guard in `scripts/test_quality_gates.sh`.
4. **`openspec/config.yaml`**: the guard is added to verification step 6. Code
   Quality gains one line saying generated sources are checked against their
   generator.
5. **Backlog**: the Q-9 row and the §8 status are updated.

Assumption recorded: the backlog names only the bridge files. The mocks are
included because they are the same kind of drift, `config.yaml` already lists
them as generator-owned, they are clean today, and checking them costs one more
command.

## Capabilities

### New Capabilities

None.

### Modified Capabilities

- `static-analysis-gates`: ADDED *Generated Source Drift Guard*.

## Impact

- **Code**: `scripts/quality_gates.sh` (+1 guard), `scripts/test_quality_gates.sh`
  (fixtures), `.github/workflows/build.yml` (install step in `quality-gates`).
  No app code changes.
- **Local runs**: the full gate now needs the generator at the pinned version
  installed. `cargo install flutter_rust_bridge_codegen --version 2.11.1` is
  already needed for verification step 2.
- **CI time**: about +15 s for generation, plus the install time (task 1.1
  measures it).
- **Read-only**: no new Kafka or Schema Registry calls. `check_read_only.sh`
  stays unchanged.

## Non-goals

- Generated localizations (`lib/l10n/*.dart`) and `lib/src/flex_theme_bridge.dart`.
  The theme bridge already does not regenerate cleanly, and Q-10
  (`material-ui-migration-tracking`) owns it. Localizations are regenerated by
  `flutter pub get` and covered by the analyzer.
- Pinning the Flutter SDK version in CI (Q-10).
- Upgrading `flutter_rust_bridge`.

## Prerequisites

None. `ci-quality-gates` (the gate script and the CI job) is already merged.
